# V1.1 — Suites configuráveis sem executar workflows reais

Este diretório contém um exemplo público e fictício do núcleo de testes. **Não é uma exportação do n8n.**

## Como usar

1. Edite `suites.example.json`: `selectedSuites` contém os IDs das suites que serão executadas.
2. Cada suite declara `id`, `version`, `adapter` e `cases` com `input` e `expected`.
3. O executor só admite os adaptadores sintéticos `ticket_normalizer` e `delivery_classifier`.
4. A validação rejeita suites desconhecidas, IDs duplicados, contratos inválidos e mais de 30 casos selecionados.
5. O resultado é `APROVADO` somente quando cada caso selecionado bate com seu resultado esperado; divergências resultam em `REPROVADO`.

```bash
node --test examples/automation-test-lab/*.test.mjs
```

O laboratório n8n de referência persiste relatórios de suites sintéticas em uma Data Table privada. O campo `duration_ms` fica **nulo** quando a duração não foi medida; resultados de versões anteriores permanecem no histórico, não são reescritos.

**Regra de segurança:** nenhuma suite permite código executável, URL externa, webhook, SQL, escrita em ClickUp ou disparo de workflows. Para integração real será exigido ambiente segregado, mocks de entrada/saída e allowlist explícita em outra versão.
